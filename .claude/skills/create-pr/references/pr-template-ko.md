# PR 템플릿 (한국어)

한국 프로젝트에 사용한다. UI 문구와 설명은 한국어로 쓴다. 코드 식별자, 파일 경로, 명령어는 원문 그대로 둔다.

## 제목 규칙

`type: 한국어 요약` 형식. type은 feat, fix, refactor, chore 중 하나이고 요약은 50자 이내, 마침표 없이 쓴다. 이 프로젝트의 커밋 컨벤션과 같다. 커밋이 하나뿐이면 그 커밋 제목을 그대로 써도 된다.

예: `feat: 프롬프트 500자 제한 검증 및 UI 연동 추가`

## 본문

```markdown
## 개요

<!-- 이 PR이 무엇을 하는지 1~3문장. 이슈가 있으면 아래에 연결 -->

Closes #

## 변경 사항

<!-- 리뷰어가 알아야 할 핵심 변경을 불릿으로. 파일 나열이 아니라 동작 변화 중심으로 -->

-

## 변경 이유

<!-- 왜 필요한지. diff나 커밋에서 확인되지 않으면 "해당 없음" -->

## 테스트

<!-- 실제로 실행한 것만 체크한다 -->

- [ ] `bun run lint`
- [ ] `bun run test`
- [ ] `bun run build`
- [ ] 직접 동작 확인

## 스크린샷

<!-- UI 변경이 있을 때만. 없으면 "해당 없음" -->

## 리뷰 포인트

<!-- 특히 봐줬으면 하는 부분, 알려진 한계, 후속 작업. 없으면 "해당 없음" -->
```

테스트 체크 항목은 프로젝트에 맞게 바꾼다. 위 명령어는 이 저장소(bun 기반) 기준이다. 다른 프로젝트라면 `README`나 `AGENTS.md`의 검증 명령으로 교체한다.
